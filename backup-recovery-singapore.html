Plan around recovery

Cloud backup is only useful if you can restore the right data.

An accidentally deleted file, an unavailable server or a failed application can interrupt the work your customers depend on. Start with what you need to recover, how much data you can afford to lose and how quickly the service must return.

Cloud backup keeps recoverable copies of supported data in a remotely hosted repository. Choose a cloud-delivered backup service or backup software paired with Axclusive-managed storage. For either approach, the proposal identifies workload compatibility, storage location, retention, capacity and recovery responsibilities. Serving Singapore customers does not mean every storage option is located in Singapore.

Choose your approach

Druva or NAKIVO: choose the backup and storage model.

Druva backup with included cloud storage

Choose a Druva backup package that includes AWS-hosted backup storage within the agreed subscription. This brings backup software and its cloud storage into one service arrangement. Supported workloads, retention, storage region, capacity and recovery terms are confirmed for your package.

NAKIVO + Axclusive-managed S3 storage

Combine NAKIVO Backup & Replication with Axclusive-managed S3-compatible storage for the backup repository. We assess workload compatibility, repository connectivity and the required storage capacity. S3-compatible describes the storage interface; this option is not a claim that the repository runs in Amazon S3.

Customer use cases

Protect the data your business needs next.

Business applications and servers

Plan recovery for agreed virtual machines, physical servers, files and databases. Confirm support for each platform and version before selecting the backup package.

Hosting and customer environments

Keep responsibilities clear between your infrastructure team, Axclusive and your customers. Define which workloads are protected, who can request a restore and how recovery is tested.

Everyday mistakes and larger incidents

Plan for file recovery as well as wider service interruption. Restoring data and bringing an entire application back online are different tasks; specify both where required.

Scope you can verify

Agree the recovery plan before the first backup.

Data and retention

List workloads, current data size, growth and retention periods. Confirm storage location, capacity, access controls and any transfer or restore charges.

Recovery targets

Set a recovery point objective (RPO): how much recent data you can afford to lose. Set a recovery time objective (RTO): how quickly the workload needs to return. Use these targets to plan backup schedules and restore tests. Actual recovery time depends on data size, connectivity and the systems being restored.

Managed responsibility

Specify setup, job monitoring, failed-job handling, restore assistance, support hours and escalation. Immutability, isolation and disaster-recovery orchestration must be explicitly included if required.

Useful answers

Cloud Backup & Recovery FAQ

Is the backup data stored in Singapore?+
Storage location is confirmed for the selected package and repository. Tell us any Singapore data-residency requirement before ordering. We assess the available region, retention and service terms; neither AWS-hosted nor S3-compatible storage automatically establishes where your data is stored.
How much does cloud backup in Singapore cost?+
Pricing depends on protected workloads, licences, data volume, retention, storage capacity and the managed tasks you select. Confirm onboarding, monitoring, restore assistance and any transfer or recovery charges. Druva includes AWS-hosted storage within the agreed package; the NAKIVO option combines software with Axclusive-managed S3-compatible storage. Neither implies unlimited capacity.
What should we test before relying on a backup?+
Test the recovery tasks you expect to need, such as a file restore or recovery of an agreed server or application. Record the restore point, elapsed time, access permissions and validation steps. Confirm who runs the test, who checks the recovered data and how gaps are addressed; a successful backup job alone does not verify application recovery.
Is storage included with the Druva option?+
Yes. Axclusive’s proposed Druva package includes AWS-hosted backup storage within the agreed subscription. The quote defines workload coverage, retention, capacity, region and any applicable charges; it is not a promise of unlimited storage.
Is Axclusive-managed S3 storage the same as Amazon S3?+
Not necessarily. S3-compatible means the storage uses a compatible interface. The NAKIVO option uses Axclusive-managed storage, with its location, capacity and service terms confirmed in the proposal.
Does backup automatically include disaster recovery?+
No. Backup protects recoverable data. Application recovery, standby infrastructure, failover and recovery exercises need their own agreed scope.
Can we include ongoing backup management?+
Yes, discuss setup, monitoring, incident handling and restore responsibilities as part of an agreed managed service. Product-only purchases do not include those activities.
